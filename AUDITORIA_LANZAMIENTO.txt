================================================================================
  RESUMEN EJECUTIVO
================================================================================

La arquitectura del proyecto es sólida: rate limiting, circuit breaker, webhooks
con firma HMAC, transacciones atómicas de créditos, workers asíncronos via QStash.
Los problemas encontrados son QUIRÚRGICOS, no estructurales. La mayoría ya fueron
resueltos en esta sesión.

Stack: React 19 + TypeScript + Vite + TailwindCSS + Firebase + Vercel
Pagos: Dodo Payments (webhooks activos)
IA: Google Gemini 3 + Seedream 4.5 (EvoLink)
Infra: Upstash Redis + QStash + Vercel Serverless

[x] SEC-01 — api/history.ts + api/gemini/content.ts sin autenticación
    CRÍTICO. Cualquiera podía leer o manipular el historial de otro usuario
    pasando un uid arbitrario en el body.
    FIX: Se agregó verifyAuth(req) al inicio de ambos handlers. El uid ahora
    viene del token Firebase verificado, no del body.
    Archivos: api/history.ts (línea 40), api/gemini/content.ts (línea 43)

[x] SEC-02 — Email admin hardcodeado en AuthContext.tsx y firestore.rules
    CRÍTICO. grancornetin@gmail.com estaba hardcodeado como fallback de admin.
    Si esa cuenta se pierde o cambia, se pierde el acceso admin en producción
    y habría que hacer redeploy urgente.
    FIX: Eliminado de AuthContext.tsx:244 y firestore.rules:41-43. El rol admin
    ahora se basa únicamente en role="admin" en Firestore.
    NOTA: Tu cuenta (bastian.herrera.2a@gmail.com) ya tiene role="admin" en
    Firestore, así que no hay impacto en ti.
    Archivos: src/modules/auth/AuthContext.tsx, firestore.rules

[x] SEC-03 — CORS aceptaba cualquier proyecto de Vercel del mundo
    ALTO. La condición origin.endsWith('.vercel.app') permitía que cualquier
    app en Vercel hiciera peticiones a tus endpoints.
    FIX: Cambiado a regex restrictivo que solo acepta luz-ia-studio*.vercel.app
    Archivo: api/_middleware.ts (línea 107)

[x] SEC-04 — RETURN_URL de pago hardcodeada en el código
    ALTO. 'https://luz-ia-studio-1.vercel.app/checkout/success' estaba quemada.
    Al cambiar de dominio (dominio propio, etc.), el checkout rompe silenciosamente.
    FIX: Ahora usa import.meta.env.VITE_APP_URL con fallback.
    Archivo: src/services/checkoutService.ts (línea 6)

[x] SEC-05 — api/avatar/clone.ts sin autenticación
    ALTO. El endpoint de clonación de avatar tomaba el uid del body sin
    verificar el token Firebase.
    FIX: Se agregó verifyAuth(req) antes del switch de acciones. El uid para
    rate limiting ahora viene del token verificado.
    Archivo: api/avatar/clone.ts

[x] SEC-06 — Rate limit en generación con uid ausente
    MEDIO. Si llega un request sin uid al endpoint de imagen (no-batch),
    todos comparten el bucket 'unknown' en Redis, lo que permite que un
    atacante degrade el servicio para otros.
    FIX: api/gemini/image.ts ahora usa verifiedUid con non-null assertion y
    retorna 401 si la autenticación falla. No existe fallback a 'unknown'.
    Archivo: api/gemini/image.ts (líneas 158-169)

[x] SEC-07 — Sin Content-Security-Policy
    BAJO. No hay CSP en vercel.json ni en index.html. Si un CDN externo
    (FontAwesome via cdnjs) es comprometido, puede inyectar JS malicioso.
    FIX: vercel.json tiene el header Content-Security-Policy configurado
    con directivas para Firebase, Google APIs, cdnjs.cloudflare.com y fonts.
    Archivo: vercel.json (líneas 40-45)

[x] UX-01 — HashRouter rompía el flujo de retorno de pago
    CRÍTICO. La RETURN_URL de Dodo apuntaba a /checkout/success, pero con
    HashRouter esa URL resuelve a la raíz en vez del componente CheckoutSuccess.
    Resultado: usuario paga pero ve la landing, no la confirmación.
    FIX: Migrado a BrowserRouter. vercel.json ya tenía el rewrite SPA correcto.
    Archivo: src/App.tsx (línea 2)

[x] UX-02 — CheckoutSuccess esperaba 3 segundos fijos para refrescar créditos
    CRÍTICO. Si el webhook de Dodo llegaba después de 3s, el usuario veía
    "¡Pago exitoso!" pero sus créditos no aparecían hasta recargar la página.
    FIX: Ahora hace polling de refreshCredits() cada 2 segundos por hasta 16s.
    Archivo: src/views/CheckoutSuccess.tsx

[x] UX-03 + UX-04 — alert() nativo y window.open(_blank) en flujo de pagos
    ALTO. alert() es bloqueado en WebView de Capacitor (App Store).

    FIX: alert() reemplazado por navigate('/login'). window.open reemplazado
    por window.location.href (misma pestaña, compatible con WebView).
    Archivos: src/views/Pricing.tsx (líneas 29-37), src/views/BuyCredits.tsx (14-22)

[x] UX-05 — NoCreditsModal tiene precios incorrectos hardcodeados

[x] UX-06 — NoCreditsModal dice "pagos se habilitarán próximamente"

--- F1. INTEGRACIÓN CAPACITOR ---

[ ] CAP-01 — Instalar y configurar Capacitor base
    CRÍTICO. El proyecto actualmente es web puro. Para App Store se necesita
    empaquetar con Capacitor (Ionic).

    Pasos:
    1. npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android
    2. npm install @capacitor/browser @capacitor/haptics @capacitor/status-bar @capacitor/splash-screen
    3. npx cap init "LUZ IA Studio" "com.luziastudio.app" --web-dir=dist
    4. npx cap add ios      (requiere macOS con Xcode instalado)
    5. npx cap add android  (requiere Android Studio)

    Crear capacitor.config.ts en la raíz del proyecto:
    -------------------------------------------------------
    import type { CapacitorConfig } from '@capacitor/cli';
    const config: CapacitorConfig = {
      appId: 'com.luziastudio.app',
      appName: 'LUZ IA Studio',
      webDir: 'dist',
      server: { androidScheme: 'https' },
      plugins: {
        SplashScreen: { launchShowDuration: 2000, backgroundColor: '#FFFFFF' },
        StatusBar: { style: 'Default', backgroundColor: '#FFFFFF' },
      },
    };
    export default config;
    -------------------------------------------------------
    Esfuerzo: 4-8 horas

DOMINIO PERSONALIZADO:
  Antes del lanzamiento público, actualizar VITE_APP_URL en Vercel con tu
  dominio final. Esto afecta la RETURN_URL del checkout (SEC-04 ya resuelto
  para que lo tome del entorno).

VARIABLES DE ENTORNO EN VERCEL:
  Verificar que en Vercel Dashboard → Settings → Environment Variables están
  configuradas TODAS las variables de .env.production. Especialmente:
  - VITE_APP_URL (el dominio final de la app)
  - DODO_PAYMENTS_WEBHOOK_SECRET
  - GOOGLE_SERVICE_ACCOUNT_KEY
  - QSTASH_TOKEN + QSTASH_CURRENT_SIGNING_KEY + QSTASH_NEXT_SIGNING_KEY
  - KV_REST_API_URL + KV_REST_API_TOKEN

FIRESTORE RULES:
  Después de modificar firestore.rules, recordar desplegarlas:
    firebase deploy --only firestore:rules
  (o desde Firebase Console → Firestore → Rules → Publish)

DODO PAYMENTS SANDBOX:
  Para testear el flujo completo de pagos sin cobros reales, cambiar
  DODO_PAYMENTS_MODE=sandbox en las variables de entorno de desarrollo.
